Highlight levels: three colours per type, each with an icon or label as well as the colour (accepted): green inside the window, orange from 75% of it (18 h for a full bowl or water, 9 h for partial), red once it expires; the early morning and late evening routine is guidance text only (accepted). No per-spot overrides: the same windows apply to every spot (accepted). | accepted |

| D-17 | One marker per spot, coloured by the worse of its food and water states (red, then orange, then green; grey only when the spot has no data at all, see D-14), so a spot just fed but never watered is red. | D-18 | Responsive: phone, tablet, desktop, mobile first. Floor is an iPhone XS, 375 x 812 px (R-13). Breakpoints 768 px (tablet) and 1024 px (desktop) live in one CSS file. | D-19 | Permissions are asked on the first load: an explanation screen, then one tap starts the browser prompts, location then camera. Refusal never blocks the app (an unlocated log is unverified, R-09); the profile says how to re-enable. The screen shows once per device, skipped when the Permissions API says both are granted. Camera is asked only because proof photos are taken with the in-app camera (not picked from the gallery, which gives fresher proof for R-09). A browser may still ask again or block repeated prompts, so nothing depends on the grant. | accepted (ask at first load); details proposed |
| D-20 | Strings: `he.json` and `en.json`, same keys, namespaced by feature (`map.title`), on the CDN under `/locales/`, loaded at runtime (react-i18next + i18next-http-backend), not bundled, so wording changes without an app release. Key types come from `en.json` (type import only). Plural keys are compared per language (Hebrew has a "two" form). If a file cannot load and none is cached, show an icon-only retry screen, since no string may be hardcoded. A new language is one JSON file plus one entry (code, direction, label) in `src/constants/`. | accepted (two files, CDN); loading details proposed |
| D-21 | Code conventions: no inline styles (no `style` attribute, no `element.style`); styles live in a `.css` file beside the component (CSS Modules), varying by class or `data-*` (e.g. the marker levels of D-14). No magic numbers in logic: limits, timeouts, sizes, counts, radii go in `src/constants/`; visual values (spacing, colours, breakpoints) in `src/styles/`. Both are lint errors, not guidance. | accepted; CSS Modules assumed |
| D-22 | Municipal stations: tiered pipeline (ArcGIS API, published lists, manual) run by a scheduled GitHub Actions workflow that opens a pull request; merge deploys one GeoJSON file to the CDN; the map reads it as a read-only layer from Phase 2 ([SOURCES.md](SOURCES.md)). Open: which geocoder for address-only lists (Nominatim allows 1 request a second and needs attribution; GovMap untested). | accepted (fetch, GeoJSON on CDN); pipeline proposed |
| D-23 | Municipal stations are public: exact coordinates are shown, since the municipality already publishes them, so R-03 would get an exception for them. They are grey until a counted log exists (D-14). From Phase 4 members can log at them: import into `spots` (upsert by `source` and `source_id`) and stop loading the file in the client; the file stays published. | proposed |
| D-24 | No domain at the start. The app, `/locales/` and `/data/` share one CloudFront distribution on its default `*.cloudfront.net` address (same origin, no CORS). Google sign-in uses the Cognito default domain `amazoncognito.com` (AWS docs); with only the basic sign-in scopes no app verification is needed. Not Netlify: its free `*.netlify.app` adds a second host, CORS and a second pipeline, and the free plan has a hard monthly credit cap that pauses sites (third-party reports: 300 credits, about 15 GB). Route 53 gives no free domain: registration is paid and a hosted zone is $0.50 a month (D-15: re-check prices). Buy one before public launch: AdSense reportedly refuses free subdomains, and moving origin later loses installs and sessions. The origin is one constant. | proposed |
| D-25 | Extensibility without speculation: boundaries are enforced by `fallow` (features never import each other, only through `index.ts`); what will grow is data, not code (languages, municipal sources, thresholds, breakpoints); an abstraction needs a second use; every convention gets a lint rule, test or hook ([extensibility.md](../.claude/instructions/extensibility.md)). | proposed |
